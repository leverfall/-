# Визуализация графа зависимостей Ubuntu APT — вариант 16

Практическая работа № 2, **этапы 1–3**. Консольный инструмент без
зависимостей от сторонних библиотек: чтение метаданных пакетов Ubuntu,
проверка параметров, построение графа зависимостей **BFS без рекурсии**.

## Структура проекта

- `src/main.py` — CLI, валидация и вывод результатов;
- `src/apt_repository.py` — получение и разбор индекса Ubuntu `Packages`;
- `src/dependency_graph.py` — тестовый граф, граф APT и обход BFS;
- `tests/` — автоматические тесты и примеры графов;
- `run.bat` / `run.sh` — запуск в Windows / Linux;
- `.gitignore` — исключения Git.

## Требования и запуск

Python 3.9 или новее. Установка зависимостей не требуется.
В Windows откройте CMD в папке проекта и запускайте **одну команду за раз**.

```bat
run.bat --package A --source tests/example_repo.txt --test-mode --version 1.0 --output graph.svg
```

Результат:

```text
Граф зависимостей (BFS):
  A: B C
  B: D
  C: D
  D: (нет)
Порядок обхода BFS: A -> B -> C -> D
```

Другие примеры для защиты:

```bat
run.bat --package A --source tests/cycle_repo.txt --test-mode --version 1.0 --output graph.svg
run.bat --package A --source tests/isolated_repo.txt --test-mode --version 1.0 --output graph.svg
```

В `cycle_repo.txt` присутствует цикл `A → B → C → A` и петля `D → D`:
BFS не зацикливается. В `isolated_repo.txt` пакет `A` не имеет зависимостей.

## Параметры

| Ключ | Назначение |
|---|---|
| `--package` | Имя пакета: для Ubuntu — Debian-имя; для теста — `A`, `B` и т.д. |
| `--source` | URL репозитория / `Packages.xz`, `Packages.gz`, `Packages` или путь к тестовому файлу |
| `--test-mode` | Использовать локальный текстовый граф вместо URL |
| `--version` | Точная версия **начального** пакета; в тестовом режиме не используется |
| `--output` | Будущее имя SVG; изображение появится только на этапе 5 |

Тестовый граф: по одному пакету на строку, например `A: B C`.
Все упомянутые пакеты должны иметь собственные строки, даже если их
зависимости пусты (`C:`). Допускаются циклы; повторные описания и неизвестные
пакеты вызывают понятные сообщения об ошибке. Имя пакета в тестовом файле
состоит из **больших латинских букв**.

## Работа с реальным репозиторием

Пример (подставьте точную версию, реально представленную в данном индексе):

```bat
run.bat --package bash --source https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.xz --version ВЕРСИЯ_ИЗ_ИНДЕКСА --output graph.svg
```

Если указать базовый URL `https://archive.ubuntu.com/ubuntu`, используется
индекс `dists/noble/main/binary-amd64/Packages.xz`. Для доступа к нему
нужен интернет. Учитываются поля `Pre-Depends` и `Depends`.

**Ограничение этапа 3:** это построение графа по **одному** индексу APT,
не полный алгоритм разрешения зависимостей менеджера `apt`. Начальный пакет
выбирается по строго заданной версии, а транзитивные пакеты берутся из
первой записи с соответствующим именем. Из альтернатив `a | b` выбирается
первая доступная в индексе; виртуальные пакеты, версии в ограничениях,
приоритеты компонентов и архитектурный выбор полностью не разрешаются.
Отсутствующие в индексе зависимости пропускаются с предупреждением.
Это особенно важно при сравнении с настоящим APT на этапе 5.

## Тестирование

```bat
python -m unittest discover -s tests -v
```

Проверяются CLI, чтение `Packages.gz` и `Packages.xz`, версии, BFS,
циклические графы, одиночные узлы, ошибочные тестовые файлы и альтернативы.
