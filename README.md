# Визуализация графа зависимостей Ubuntu APT — вариант 16

Практическая работа № 2, **этапы 1–4**. Консольный инструмент без
зависимостей от сторонних библиотек: чтение метаданных пакетов Ubuntu,
проверка параметров, построение графа зависимостей **BFS без рекурсии**, а также
определение порядка загрузки пакетов.

## Структура проекта

- `src/main.py` — CLI, валидация и вывод результатов;
- `src/apt_repository.py` — получение и разбор индекса Ubuntu `Packages`;
- `src/dependency_graph.py` — тестовый граф, граф APT и обход BFS;
- `src/load_order.py` — топологическая сортировка зависимостей;
- `tests/` — автоматические тесты и примеры графов;
- `run.bat` / `run.sh` — запуск в Windows / Linux;
- `.gitignore` — исключения Git.

## Требования и запуск

Python 3.9 или новее. Установка зависимостей не требуется.
В Windows откройте CMD в папке проекта и запускайте **одну команду за раз**.

```bat
run.bat --package A --source tests/example_repo.txt --test-mode --version 1.0 --output graph.svg --load-order
```

Результат:

```text
Граф зависимостей (BFS):
  A: B C
  B: D
  C: D
  D: (нет)
Порядок обхода BFS: A -> B -> C -> D
Порядок загрузки: D -> B -> C -> A
```

Другие примеры для защиты:

```bat
run.bat --package A --source tests/cycle_repo.txt --test-mode --version 1.0 --output graph.svg --load-order
run.bat --package A --source tests/isolated_repo.txt --test-mode --version 1.0 --output graph.svg --load-order
run.bat --package A --source tests/chain_repo.txt --test-mode --version 1.0 --output graph.svg --load-order
```

В `cycle_repo.txt` присутствует цикл `A → B → C → A` и петля `D → D`:
BFS не зацикливается; при запросе `--load-order` программа отдельно объясняет,
что циклический граф нельзя упорядочить так, чтобы все зависимости шли раньше
зависящих пакетов. В `isolated_repo.txt` пакет `A` не имеет зависимостей.

## Параметры

| Ключ | Назначение |
|---|---|
| `--package` | Имя пакета: для Ubuntu — Debian-имя; для теста — `A`, `B` и т.д. |
| `--source` | URL репозитория / `Packages.xz`, `Packages.gz`, `Packages` или путь к тестовому файлу |
| `--test-mode` | Использовать локальный текстовый граф вместо URL |
| `--version` | Точная версия **начального** пакета; в тестовом режиме не используется |
| `--output` | Будущее имя SVG; изображение появится только на этапе 5 |
| `--load-order` | Дополнительно вывести порядок загрузки (этап 4) |

Тестовый граф: по одному пакету на строку, например `A: B C`.
Все упомянутые пакеты должны иметь собственные строки, даже если их
зависимости пусты (`C:`). Допускаются циклы; повторные описания и неизвестные
пакеты вызывают понятные сообщения об ошибке. Имя пакета в тестовом файле
состоит из **больших латинских букв**.

## Работа с реальным репозиторием

Пример (подставьте точную версию, реально представленную в данном индексе):

```bat
run.bat --package bash --source https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.xz --version ВЕРСИЯ_ИЗ_ИНДЕКСА --output graph.svg
```

Если указать базовый URL `https://archive.ubuntu.com/ubuntu`, используется
индекс `dists/noble/main/binary-amd64/Packages.xz`. Для доступа к нему
нужен интернет. Учитываются поля `Pre-Depends` и `Depends`.

**Ограничение этапа 3:** это построение графа по **одному** индексу APT,
не полный алгоритм разрешения зависимостей менеджера `apt`. Начальный пакет
выбирается по строго заданной версии, а транзитивные пакеты берутся из
первой записи с соответствующим именем. Из альтернатив `a | b` выбирается
первая доступная в индексе; виртуальные пакеты, версии в ограничениях,
приоритеты компонентов и архитектурный выбор полностью не разрешаются.
Отсутствующие в индексе зависимости пропускаются с предупреждением.
Это особенно важно при сравнении с настоящим APT на этапах 4–5.

## Этап 4 — порядок загрузки и сравнение с APT

Ребро `A -> B` означает, что пакет `A` зависит от пакета `B`.
Для вывода порядка используется **топологическая сортировка алгоритмом Кана**
(без рекурсии). При наличии нескольких вариантов выбирается следующий
пакет по имени в лексикографическом порядке. Таким образом:

- Ромб `A: B C; B: D; C: D; D:` → `D -> B -> C -> A`.
- Цепочка `A: B; B: C; C:` → `C -> B -> A`.
- Одиночный пакет `A:` → `A`.
- Цикл `A: B; B: A` → сообщение об отсутствии корректного порядка.

**Сравнение с настоящим APT на Linux/Ubuntu** (запускать там, где установлен
`apt`; на Windows CMD такие команды обычно не доступны):

```sh
apt-cache depends bash
apt-cache depends --recurse --no-recommends bash
apt-get -s install bash
```

Команда `apt-get -s install bash` **симулирует** установку и не изменяет
систему. Для сравнения выбранной версии можно использовать
`apt-get -s install 'bash=ВЕРСИЯ'`, если она присутствует в настроенных
репозиториях. Следует сохранить вывод APT и нашей программы для анализа.

Наше приложение рассчитывает **допустимый топологический порядок по модели**;
это не фактический порядок сетевых скачиваний или действий `apt`.
В частности, APT учитывает уже установленные пакеты, разные индексы,
архитектуры, ограничения версий, виртуальные пакеты, альтернативы,
`Pre-Depends`, пакеты разных компонентов и особенности циклических связей.
Наша модель использует один индекс и упрощённый выбор транзитивных версий,
поэтому результаты **могут отличаться**. Сравнение с реальным запуском APT
следует выполнить на Ubuntu и зафиксировать его наблюдаемый вывод;
в архив не включается выдуманный результат сравнения.

## Этап 5 — Graphviz DOT и SVG

При каждом запуске программа сохраняет два файла: SVG с изображением графа
по пути `--output` и Graphviz DOT с тем же именем, но расширением `.dot`.
DOT содержит описания всех достижимых узлов и дуги `A -> B`, означающие,
что `A` зависит от `B`.

Если установлен `dot` из Graphviz и доступен в PATH, SVG создаётся им.
Иначе применяется встроенный SVG-рендерер Python (пакеты не устанавливаются).
Сгенерированный DOT можно отдельно визуализировать командой
`dot -Tsvg graph.dot -o graph_graphviz.svg`.

Три примера визуализации разных пакетов из **тестового** репозитория:

```bat
run.bat --package A --source tests/example_repo.txt --test-mode --version 1.0 --output graph_A.svg
run.bat --package B --source tests/example_repo.txt --test-mode --version 1.0 --output graph_B.svg
run.bat --package C --source tests/example_repo.txt --test-mode --version 1.0 --output graph_C.svg
```

Откройте `graph_A.svg`, `graph_B.svg`, `graph_C.svg` в браузере.
Для каждого файла также создаётся `.dot`.

### Сравнение результатов со штатным APT

На Ubuntu можно получить штатное текстовое описание графа командой
`apt-cache depends --recurse --no-recommends bash`, а граф через
`apt-rdepends bash` (если этот инструмент отдельно установлен) и Graphviz
либо иной установленный просмотрщик зависимостей. Сам APT не имеет
обязательного встроенного экспорта SVG в базовой команде `apt-cache`.
Сравнивать нужно список вершин/рёбер, а не координаты SVG.
Наш инструмент анализирует один указанный индекс, тогда как APT использует
все настроенные репозитории, архитектуры, ограничения версий и сведения об
установленных пакетах. Поэтому возможны различия. **Реальное сравнение
на Ubuntu нужно выполнить отдельно и сохранить наблюдаемый вывод** —
архив содержит тестовую демонстрацию, но не выдуманные реальные результаты.

`tests/test_visualization.py`. Для запуска всех тестов:
`python -m unittest discover -s tests -v`.
